# Windows 3.2.1 原始播放封面验收

2026-10-10，Codex。Yves 要求“读取到啥就提取啥”。已取消 3.2.0 自动封面的 512 像素缩放和 JPEG 重编码，直接保存 Windows 媒体会话提供的原始图片字节。

## 当前行为

原生只读取图片流、检查可解码格式/体积/像素和等待边界，随后把同一流的原字节编码成 Data URL。通过实际 WinRT 类型反射核对 `DecoderInformation.MimeTypes`，按解码器识别的格式输出 PNG/JPEG/WebP/GIF/BMP；不依赖提供者自行声称的 MIME。图片字节不经过绘图、缩放或重新编码，透明度、编码元数据和原有尺寸由原字节保留。

保留 4 MiB、20 MP、4.5 秒保护，动画帧累计像素也计入；超限跳过图片，不静默压缩，歌曲读取继续。前端去掉 512 限制并同步大小/像素预算；IPC 缓冲仅在请求图片时放宽为 8 MiB，容纳 4 MiB 的 Base64 JSON。草稿、SQLite 和备份仍使用现有存储/JSON v6，无数据库结构更改。已有手动封面和已存封面继续优先，不自动替换旧图片。

原样提取指保留播放器交给系统的图片。系统只给 120 像素缩略图时，不代表已取得播放器内部的高清原图；本轮没有另加网络高清封面来源。

## 验证

- 真实 WinRT 原生检查 15 项通过：768×384 透明 PNG、1024×640 JPEG/BMP/GIF 和小图的输入/输出字节一致，五组 SHA-256 全部一致；大图不再被缩到 512。无图、坏图、4 MiB 超限、20 MP 超限与超时预算安全降级。
- 最终 EXE 的 10 组 Electron/真实 SQLite 专项通过；960×640 PNG 的编码长度大于原 1,400,000 字符上限，仍可预览、保存草稿、恢复、正式保存和导出完整备份。输入、SQLite、完整备份 SHA-256 一致，页面错误为 0。手动封面、身份变更、迟到响应、切歌和无图回归仍通过。
- 最终 EXE 实播酷狗《Ditto》通过原生读取、预览、隔离 SQLite 保存、重启回读及速记预览。播放器提供 PNG 120×120 / 32,730 字节，歌手 NewJeans；未读到可确认的专辑时保留空值。没有操作用户播放/暂停、播放器设置或正式档案。
- 类型检查、桌面构建、NowPlaying 12/12 用例及最终包 98 项 ZIP 校验通过；原生运行源码和包内文件摘要一致。没有重复前一阶段不受影响的全量 17 组 Windows 回归。
- 首轮原生用例按预期拒绝旧 JPEG 重编码输出。后续检查捕获 Windows PowerShell 5.1 的换行运算符语法错误，修正后通过。大图的 Playwright fullPage 截图曾超时，已沿用既有 Windows QA 的 `webContents.capturePage` 捕获实际窗口；失败 JSON 保留，最终 10 组全通过。

证据集中在 `release/codex_windows_raw_cover_acceptance_20261010/`，包括原生输入/输出摘要、最终 EXE 大图往返摘要、实际酷狗原 PNG 和页面截图。合成 profile 和一次性检查脚本按持续授权清理，结果见该目录 `codex_cleanup_checks.json`。3.2.0 交付和验收证据保留。
